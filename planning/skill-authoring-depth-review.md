## Decision

Use the HASE declarative skill format and enrich the decisions that each
Registry package leaves implicit. Evaluate the whole package: core, references,
exercises, source authority and receiving evidence. Depth means sufficient
specificity to act and recover; core length supplies a routing observation.

Four routes were considered: retain every existing core, impose a comprehensive
uniform template, enrich material gaps by package, or create a new authoring
framework and validator. Select package-specific enrichment. The existing
HASE authoring contract already owns this job, and the Registry's existing
package validator owns metadata, dependency closure and publication boundaries.

## Review questions

For each package, can a collaborator:

1. Recognize its coherent job and a nearby poor-fit case from the available routing and contract?
2. Obtain the necessary inputs, identify missing information and choose a proportionate default?
3. Make the consequential decisions from named rules and the ordered method?
4. Reach each needed reference directly, with the load condition visible?
5. Distinguish examples, executable controls, observed use and open transfer claims?
6. Preserve source, authority and state through failure or interruption, then find the next receiver?
7. Recognize completion and the event that makes re-entry useful?

The review uses these questions as a design lens. It creates neither a numeric
quality score nor a mandatory section checklist. Exact-version artifact and
schema source remain unchanged; the current skill instructions and their
public projection receive the enriched method.
