# Deterministic DTCG and Style Dictionary pipeline 0.1.0

## Practical value

This executable carries reviewed visual meaning from a finite design-token
contract into CSS custom properties, an immutable JavaScript map, and matching
TypeScript declarations. It gives collaborators an exact place to inspect a
source problem, a semantic change, a generated artifact, or an interrupted
promotion.

The package implements the DTCG Format Module 2025.10 subset named in
[`config/compatibility-envelope.json`](config/compatibility-envelope.json).
The DTCG report carries Final Community Group Report standing.
Style Dictionary 5.7.0 supplies the compiler, and the artifact-local lockfile
binds its dependency graph.

## Run the example

From the repository root:

```sh
npm --prefix snippets/style-dictionary-dtcg-pipeline/0.1.0 ci --ignore-scripts
npm --prefix snippets/style-dictionary-dtcg-pipeline/0.1.0 test
npm --prefix snippets/style-dictionary-dtcg-pipeline/0.1.0 run example
```

The example builds in an isolated temporary directory, prints the admitted
graph and semantic diff, reports source bytes, elapsed time, and peak resident
memory, then removes its candidate files. The deterministic manifest records
the canonical candidate-input paths, byte counts and digests alongside the
aggregate source digest, compiler coordinate, output digests, file count, and
generated bytes. Manifest formation compares those captured inputs with the
current authored sources and returns the build as the restart point when either
side has changed. The build observation records the Node.js, operating-system,
and architecture coordinate separately so the artifact family keeps one
content identity across the supported runtime envelope.

## End-to-end contract

```text
authored token layers
  → bounded DTCG admission
  → reference graph and target-name validation
  → sorted brand × mode coordinates
  → fresh Style Dictionary instance per coordinate
  → CSS + JavaScript + TypeScript candidates
  → inventory, syntax, parity, and digest checks
  → one content-addressed accepted coordinate
  → one atomic accepted pointer
```

The source layers separate primitives, semantic aliases, component/state
bindings, and intentional brand/mode overrides. Source layers keep one owner
per token path; the final variant layer owns explicit coordinate overrides.
Every asynchronous compiler call and injected pre-coordinate hook is awaited.

## Inspecting a change

`semanticDiff()` separates:

- added and removed token identities;
- changed types;
- changed descriptions and extensions;
- changed alias targets, including component/state bindings; and
- changed resolved values.

Brand and mode belong to the build coordinate, so a reviewer compares exact
coordinates and keeps mode identity explicit. The included
Acme-to-Research comparison demonstrates alias-target changes flowing into
resolved component values.

## Inspecting a failure

Focused fixtures return typed failures with a stage, affected coordinate, and
restart point:

| Boundary | Typed result | Recovery |
| --- | --- | --- |
| unresolved alias | `UNRESOLVED_REFERENCE` | restore the referenced token in source |
| circular alias | `ALIAS_CYCLE` | revise the reported reference path |
| type mismatch | `REFERENCE_TYPE_MISMATCH` | align the declared semantic type |
| unsupported subset feature | `UNSUPPORTED_DTCG_FEATURE` | extend and review the envelope or select an admitted type |
| duplicate source owner | `SOURCE_COLLISION` | assign one source owner or declare a variant override |
| generated-name collision | `NORMALIZED_NAME_COLLISION` | choose distinct target-safe paths |
| private or secret-shaped source text | `SOURCE_BOUNDARY_REJECTED` | supply a reviewed public source snapshot |
| incomplete Figma mode | `FIGMA_MODE_VALUE_REQUIRED` | provide the required coordinate value |
| interrupted promotion | injected promotion fault | resume from the preserved accepted pointer |

The Figma-shaped adapter is a pure, synthetic boundary example. It returns a
DTCG candidate and bounded source map after checking supported types, required
modes, normalized identities, and approved public text. Live Figma credentials,
file keys, and service calls belong to a separately reviewed adapter.

## Complexity and resource envelope

Graph admission uses indexed token and normalized-name maps. For `N` tokens
and `E` alias edges, admission and cycle/depth analysis perform `O(N + E)`
work with `O(N + E)` storage. The tests exercise 100, 1,000, and 10,000-token
graphs, high fan-out, and the finite alias-depth envelope. Iterative preflight
and graph traversal return typed depth boundaries for deeply nested layers,
reverse-ordered alias chains, and Figma-shaped snapshots while the bounded
pipeline retains control. Source-node and aggregate UTF-8 string-byte ceilings
are evaluated before token values are cloned. File size is admitted from stat
metadata and rechecked through capped reads, so sparse and growing files stay
inside the same allocation envelope. A map lookup replaces a repeated
full-dictionary scan with linear graph work.

The build observation records source bytes, coordinate and platform counts,
expected files, elapsed time, and peak resident memory. The deterministic
manifest carries stable source and output facts; variable runtime measurements
remain in the observation receipt so two clean manifests can match byte for
byte. Ordinal code-point ordering supplies the canonical sort across operating
system locales.

## Publication and recovery

Each candidate build claims one empty caller-selected directory with an
exclusive ownership marker. Existing caller material remains in place, and a
second writer selects another empty directory. Verification confirms the
expected file catalog, media types implied by extensions, balanced CSS,
distinct custom-property names, immutable JavaScript, declaration coverage,
digests, and byte/file ceilings before artifact bodies enter memory.
Verification admits contained regular files,
rejects symlinks at every candidate path component, and parses the generated
JavaScript module as static data. Candidate code stays inert while CSS,
JavaScript, and declaration inventories are compared. Promotion copies the verified family into a
manifest-digest directory only after the closed manifest envelope, exact source
size, and source digest pass, and then atomically replaces
`accepted/current.json`.
A repeated digest rechecks the stored manifest digest, exact file inventory,
byte counts, and file digests before the pointer moves. Promotion carries only
the artifacts named by that manifest into the accepted coordinate. Every
publisher owns a distinct staging directory, so concurrent replay of the same
manifest converges on one verified digest directory and one atomic pointer.
After the digest directory verifies, an injected stop before pointer movement
preserves the previous pointer and leaves those immutable accepted bytes ready
for retry. A separate retention policy may collect unreferenced digest
directories after their review and recovery window.

## Adapting the package

1. Name the receiving decision, owners, brands, modes, and targets.
2. Extend the compatibility envelope through a reviewed version change.
3. Keep primitive, semantic, component, and variant ownership explicit.
4. Add accepted and rejected fixtures for each new type or transform.
5. Add receiver-focused semantic-diff categories when new meaning enters.
6. Build with one fresh compiler instance for each finite coordinate.
7. Verify the complete candidate family before moving one accepted pointer.
8. Record the runtime, lock, inputs, outputs, and observation coordinate.

## Official sources and version scope

- [DTCG Format Module 2025.10](https://www.designtokens.org/TR/2025.10/format/)
  defines the stable format behavior used by this subset.
- [DTCG technical reports](https://www.designtokens.org/technical-reports/)
  distinguish stable and draft modules.
- [Style Dictionary 5.7.0 package coordinate](https://github.com/style-dictionary/style-dictionary/blob/v5.7.0/package.json)
  identifies the exact compiler and Node engine.
- [Style Dictionary configuration](https://styledictionary.com/reference/config/)
  documents asynchronous build APIs, platforms, transforms, and formats.
- [Style Dictionary DTCG utilities](https://styledictionary.com/reference/utils/dtcg/)
  documents DTCG-aware conversion behavior.
- [Figma Variables REST API](https://developers.figma.com/docs/rest-api/variables/)
  supplies the service boundary that a future live adapter must version and
  authorize independently.

Claims here stay bound to DTCG Format Module 2025.10, Style Dictionary 5.7.0,
the artifact lock, and the included synthetic fixtures. A production token
authority supplies its approved types, extensions, naming policy, modes,
targets, security review, and release acceptance.
