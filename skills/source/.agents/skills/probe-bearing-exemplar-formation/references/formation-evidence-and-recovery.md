# Formation evidence and recovery

Use this guide when a first artifact must distinguish exact source selection,
adapted behavior, and an illustrative proposal. Its reader should be able to
tell which claim can be run, inspected, or revisited without access to private
collaboration history.

## Source relationship selects the proof

| Form | Required source relationship | Material observation |
| --- | --- | --- |
| Exact excerpt | Public owner, immutable revision, file and selection rule; preserve required notices. | Byte comparison plus the owning behavior test. An excerpt's digest establishes identity. |
| Adapted runnable example | Named upstream source/license and the changes that make the package self-contained. | Execute the adaptation with an independently derived result and a fault that distinguishes its claim. |
| Synthetic teaching example | Explicit authored fixture and the real mechanism it illustrates. | Check arithmetic/state relationships against stated expectations; preserve the difference between illustration and observed domain data. |
| Proposed design probe | Experimental standing, unresolved guarantee, and the decision it will inform. | A falsifiable experiment or precise next observation; accepted implementation remains separately identified. |

Public citation permission and source license remain distinct. Preserve the
attribution and license that govern the reused material, and keep gated
locators with their authorized resolver. A public-safe semantic source name
can preserve lineage while an owner resolves disclosure.

## A runnable package carries the decisive context

Start with one command and its actual requirements: runtime, dependencies,
input shape, resource ownership, expected result, cleanup, and execution limit.
Keep a minimal independent oracle close to the behavior. If the result depends
on a tenant predicate, null state, timestamp convention, or unit, include a
fixture that changes the result when that distinction changes.

A SQL example may prove counts under a fixed role and synthetic population.
Its ordinary-role execution, constraint behavior, and plan are separate
observations. Application authentication, production data distribution, full
response allocation, and crash recovery enter only through their own checks.
Likewise, a successful JSON decode establishes syntax; admitted domain values
need the domain contract's separate observation.

## Failure preserves a useful candidate

1. Keep the smallest reproducible fault and the exact source/runtime coordinate.
2. Identify whether the failure changes implementation, fixture meaning, source
   lineage, or only an environment prerequisite.
3. Repair the owning layer, or narrow the candidate's evidence standing and
   name its next receiver.
4. Repeat the decisive observation before generating source-supported
   companions. Update digests from the resulting bytes through their owner.
5. Verify every independently retrieved representation carries its question,
   source relation, evidence boundary, and complete-package route.

If a proof allocates a process or filesystem resource, its cleanup result is
part of the return. Preserve any failed resource's private recovery coordinate;
publish only the normalized mechanism and disposition.

## Small review exercise

Given a sample whose query is correct only when pending means “undelivered,”
compare three candidate packages: query text alone; query plus representative
rows; query, explicit predicate, independent expected counts, and a deliberate
predicate perturbation. Select the smallest package that supports the stated
claim. If the claimed result is merely explaining syntax, the text-only form
can suffice; if the claim is executable count correctness, the distinguishing
fixture and oracle become material.

This is an authored review exercise. Record an actual receiving use separately,
including whether it changed the artifact, the decision, or only orientation.
