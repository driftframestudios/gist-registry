# Visual artifact family publication

Use this skill when one visual needs to travel as responsive pixels, meaningful
prose or structured data, and a recoverable release coordinate.

## Start here

1. Read the [skill contract](SKILL.md).
2. Name source ownership, rights, purpose, dimensions, and descriptions.
3. Run the [family admission exercise](exercises/README.md).
4. Open [renderer, SVG, and metadata boundaries](references/renderer-svg-and-metadata-boundaries.md)
   when output bytes or browser behavior affect acceptance.

## Success example

A source-owned process diagram produces 640, 1280, and 1600 pixel WebPs, an
accessible HTML gallery, and a semantic JSON companion. The compiler verifies
SVG IDs, local references, connector painter order, metadata standing,
dimensions, digests, and repeated bytes before moving the accepted pointer.

## Recovery example

An SVG repeats a clip-path ID. Source admission returns the repeated identity
before rendering, keeps the accepted derivative family live, and restarts from
the authored SVG after repair.

## Maturity

`exercised`: a synthetic SVG family and a deterministic token-artifact family
have used source contracts, finite target matrices, semantic companions,
digest manifests, and accepted-pointer recovery. A receiving product supplies
its own art direction, rights review, cache policy, and release observation.
