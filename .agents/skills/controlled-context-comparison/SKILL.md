# Controlled context comparison

## Contract

- **What:** Construct paired observations that isolate a declared input change while preserving source evidence, admissible dependencies, output classes, and accountable interpretation.
- **When:** A team asks whether an administrative, contextual, policy, presentation, or model-input difference changes a downstream result.
- **Boundaries:** A controlled software experiment establishes behavior within its declared construction. Wider causal, population, fairness, and operational claims retain fitting designs and accountable reviewers. Current task authority governs data access, model calls and downstream actions.
- **Result:** A versioned pair specification, independent invariants and expected effects, complete outcome accounting, and a bounded interpretation for one receiving decision.

## Fit and attention

- **Useful when:** Input generation can leak target information, one changed field affects several stages, or stochastic output complicates interpretation.
- **Poor fit when:** A direct source comparison answers a deterministic equality question, or several uncontrolled factors require a broader study design.
- **Smallest useful dose:** One pair, one material contrast, one independent expected effect and one receiving decision.
- **Foregrounds:** Intervention meaning, construction order, permitted downstream changes and every attempted outcome.
- **May under-attend:** Historical selection, institutional context and population effects that a constructed pair cannot represent; route those questions to the study owner.
- **Interactions:** [Parity-bound workload measurement](https://kindlight.io/skills/parity-bound-workload-measurement/) owns cost comparison after behavioral equivalence. This skill owns what changed and which interpretation the pair supports.

## Inputs, defaults and output

Bring the receiving question and reviewer; source identity and provenance;
the changed concept and its allowed values; fixed facts and permitted dependent
transformations; observable output families; available execution authority;
and a stopping rule. Include policy jurisdiction/effective dates when they
change the intervention's meaning.

For a missing invariant, expected effect or admissible dependency, first return
a pair-design question and the observation needed to resolve it. Use source
inspection or an authored deterministic fixture while external execution
remains outside the task grant. A missing arm retains its own outcome.

Return the pair specification, control results, all attempted outcome classes,
observed differences by output family, bounded inference and next receiver.
Keep sensitive case material with its authorized source owner.

## Rules

### Rule: The intervention names one concept at one level

A raw label, normalized class, eligibility state, policy decision and output
action are distinct variables. State which one changes, at which construction
stage, and why any dependent transformation belongs to that intervention.
Compare task meaning before bytes: a leaf code can add information relative to
its parent category. That pair then needs an equivalent-information design or
a separately named information-content question.

### Rule: Invariants retain independent identities

Bind source evidence by identity or digest before constructing either arm.
Record the sequence of normalization, feature derivation, retrieval and prompt
assembly. A target-derived feature remains visible as target-dependent
information. Admit only the declared intervention and its justified dependent
changes; a source mismatch returns to construction before outcome comparison.

### Rule: Output families retain their own interpretations

Separate scientific/source-evidence conclusions, administrative routing,
workflow burden, explanation and authorized effects. A changed administrative
route may be the intended effect while scientific classification stays fixed.
A material difference goes to its mechanism owner and reviewer; classify the
expected behavior before diagnosing an implementation defect.

### Rule: Controls challenge both silence and difference

Specify an unchanged-input control and a designed effect with an independent
expected result. The positive control must distinguish an observer that always
reports agreement. Deriving the oracle from the comparator's own output leaves
that distinction untested. Preserve the source of each expectation.

### Rule: Execution variation remains observable

Hold model, prompt, retrieval, tool and dependency versions constant where the
design permits; record actual routing, ordering and residual stochasticity.
A fixed seed supports only its demonstrated repeatability. If uncontrolled
variation dominates the contrast, return an indeterminate observation and
select a fitting repeat or blocked design before widening interpretation.

### Rule: Every attempted arm belongs to the result

Retain observed, incomplete, failed, abstained and rejected states with their
own denominators. Paired agreement uses complete admissible pairs, alongside
the attempted-pair and failure counts. Preserve the reason a pair leaves that
analysis so selective completion remains visible. Records and repeated runs
from one subject or episode stay clustered under the declared inference unit.

## Operating sequence

1. **Frame:** Bind the task, scenario, decision, source, relevant policy dates and accountable reviewer.
2. **Specify:** Name the changed concept, fixed facts, permitted dependencies, output families and inference unit.
3. **Challenge:** Define independent invariants, unchanged and designed-effect controls, outcome classes and stop condition.
4. **Admit and execute:** Verify both arms, then use the granted environment. Record actual versions, order and all attempts.
5. **Interpret:** Separate designed effects, invariant breaks, ordinary failures and unresolved variation. Match uncertainty to the unit of inference.
6. **Return:** Deliver one bounded disposition with its mechanism owner and next evidence or authority event.

## Scenarios

### Scenario: Equivalent evidence and distinct routing

- Given identical measurement evidence and a review status intervention,
- When both arms pass source admission and the observer sees the designed routing change,
- Then scientific classification agrees, workflow disposition differs, and the result names those two output families separately.

### Scenario: One arm fails

- Given two attempted arms and one completed observation,
- When the other arm fails or abstains,
- Then the result retains both attempts and the failure category, with paired agreement unresolved; recovery reruns the declared pair or applies a prespecified missing-outcome method.

These scenarios describe decisions. The linked exercise implements the authored
deterministic cases; a new domain or model requires its own receiving evidence.

## Recovery and re-entry

A failed invariant returns to pair construction with both source identities
preserved. A failed observer returns to the observer owner with its control
result. An interrupted run retains completed attempts and marks the pair
incomplete; the invoking task owns durable checkpointing. A changed task,
source, policy, model or dependency reopens the affected design and controls.

## Completion

Complete when the receiver can identify what changed, what stayed fixed,
which effect is supported, every outcome class, the evidence boundary and the
next decision. An indeterminate result is a complete return when it names the
specific missing observation. Release the method until new evidence changes
that decision.
